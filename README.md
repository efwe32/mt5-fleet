# MT5 批量终端 · 多账户实盘版

在一台 Windows 电脑上同时管理多个 MetaTrader 5 账户：批量登录、实时查看余额/净值/浮盈/持仓、一键批量下单、按条件批量平仓、批量改止损止盈、撤挂单、批量部署/停止 EX5 策略、收益统计、操作日志。界面在本机浏览器里打开（`http://127.0.0.1:8765`），布局和网页演示版一致，但这里是**真的连接 MT5 终端并真实交易**。

> 本程序**只有实盘模式**：确认后的下单、平仓、改单、撤单、部署都会立即真实发送到券商。每个批量操作都会先弹出确认框，并受“单笔最大手数”和“单次批量合计最大手数”保护。首次使用请用最小手数逐项验证。

## 一、和你桌面上的 MT5 完全隔离（重要）

你电脑上已经在用的 MT5 **不会被本程序碰到**：

| 规则 | 说明 |
|---|---|
| 只用自己文件夹里的终端 | 只接受 `D:\15\terminals\<账号>\terminal64.exe` 这样的路径，填别的路径（比如 `C:\Program Files\MetaTrader 5\...`）会直接拒绝。`terminals\base` 是模板，不能直接登录。 |
| 永远带明确路径 | 程序调用 `mt5.initialize()` 时**一定**带上该账户的 `terminal64.exe` 路径和 `portable=True`，从不让 MetaTrader5 包自己去找"默认终端"（那样可能连到你桌面上的 MT5）。没有路径就拒绝登录。 |
| 永远便携模式 | 程序自己用 `terminal64.exe /portable` 启动每个受管终端，数据、配置、图表、EA、日志都留在它自己的文件夹里，**不读写 `%APPDATA%\MetaQuotes`**，不会改你桌面 MT5 的设置、账户、图表。 |
| 不接管别人开的终端 | 如果某个 `terminals\<账号>` 里的 MT5 已经在运行，但不是本程序启动的（比如你手动双击打开的），登录时会提示"不是本程序启动的，请先关闭"，不会去接管。 |
| 只关闭自己启动的进程 | 程序启动终端时记录 **PID + 进程启动时间 + exe 路径**（保存在 `data\launched.json`）。重启终端、断开时关闭、退出时关闭，都只针对这些登记过且三项都对得上的进程；**从不按进程名结束 terminal64.exe**，也不会动别的 MT5。 |
| 别的 MT5 只读 | 模板 MT5（如 `MetaTrader 5    4`）只被复制、从不写入；「导入服务器列表」只读取你选的那份 MT5 的 `Config\servers.dat`，只有你打开导入窗口时才会查看 `%APPDATA%\MetaQuotes\Terminal\*\origin.txt` 来找数据目录。 |
| 一个终端一个账户 | 两个账户填同一个终端路径会被拒绝（MT5 一个终端同时只能登录一个账户）。 |

- Windows 10 / 11（64 位）

## 三、快速开始（4 步）

1. **安装依赖**：双击 **`安装依赖.bat`**（检查 Python、创建 `.venv`、安装 `fastapi uvicorn psutil MetaTrader5`，官方源失败自动改用清华镜像）。只需第一次运行。
2. **启动**：双击 **`一键启动.vbs`**（不显示窗口），浏览器自动打开 `http://127.0.0.1:8765/`（端口被占用会自动换下一个）。退出用网页左下角「退出程序」或 `停止后台.bat`。需要看运行信息时用 `调试启动（显示窗口）.bat`。
3. **面板里添加并登录**：账号页 → **添加并登录** → 填 账号、交易密码、服务器（输入框会提示用过的服务器名）、分组、名称 → 点「添加并登录」。要一次加很多个，切到「批量粘贴」，每行一个：
   ```
   账号,密码,服务器[,分组,名称]
   51002811,交易密码,ICMarketsSC-MT5,主仓,主仓 · 黄金
   88011203,交易密码,Pepperstone-Edge-Live,跟单,跟单 A
   ```
   （逗号、中文逗号或 Tab 分隔都行，一次最多 200 行。）窗口里每个账户会依次显示：**创建副本 → 启动终端 → 登录 → 算法交易已开启**，失败的账户会用中文写明原因，其它账户不受影响。
4. **上传 EA 并分发**：策略页 →「1 上传 EA 到 EA 库」选 `.ex5`（可同时选 `.set`）→ 点 EA 或「分发…」→ 选账户（全部在线 / 按分组 / 逐个勾选）、品种、周期、魔术号 → 点 **分发**。每个账户自动：**登录（没登录的先自动登录）→ 复制 EA 文件 → 重启终端 → 挂载 EA → 校验**，完成后 EA 就在该账户上以“算法交易”方式运行。

## 五、一键登录在后台做了什么

1. **创建副本**：`terminals\<账号>\` 不存在时，从模板复制一份（先复制到 `<账号>.copying`，完成后再改名，中途失败不会留下半成品）。跳过 `Bases`（历史数据）、`logs`、`Tester`、`Config\accounts.dat`（模板里别人的登录记录）。模板默认自动查找：`terminals\base` 优先，其次程序目录里的 `MT5模板`，再其次 `D:\15` 里其它带 `terminal64.exe` 的文件夹（新的优先）；也可以在 **设置 → 模板 MT5** 里指定并点「检测」。**模板本身从不写入**，就算它正开着也只是读取。
2. **启动终端**：如果导入过服务器列表，先把它放进这个副本的 `Config\servers.dat`（原文件备份为 `servers.dat.fleetbak`，只对没在运行的副本做）。然后在副本目录写一个随机名的一次性配置文件 `fleet_xxxx.ini`，用 `terminal64.exe /portable /config:fleet_xxxx.ini` 启动：
   - `[Common]` Login / Password / Server，`KeepPrivate=1`（让终端自己记住密码，下次重启无需再填），`NewsEnable=0`；
   - `[Experts]` `Enabled=1`（打开「算法交易」）、`AllowLiveTrading=1`、`AllowDllImport` 按设置页「允许 EA 调用 DLL」。
3. **登录**：`mt5.initialize(path=该副本的 terminal64.exe, login, password, server, portable=True, timeout)`。第一次失败（常见于终端还在搜索服务器）会等待约 12 秒自动重试一次；密码错误等明确失败不会反复重试。
4. **删除配置文件**：不论成功失败，`initialize` 返回后立刻把 `fleet_xxxx.ini` 用零覆盖再删除；程序启动时和每次启动终端前也会清理残留的 `fleet_*.ini`。
5. **整理图表**（在第 2 步启动终端之前做；设置「启动终端时只保留一个图表」默认是）：把这个副本里没有挂 EA 的普通图表移到 `terminals\<账号>\fleet_backup\charts-时间\`（不删除），只留一个默认品种/周期（USDJPYc M15）的图表；挂着 EA 的图表保留。登录后把默认品种加入「市场报价」。
6. **检查算法交易**：读取 `terminal_info().trade_allowed`、`account_info().trade_allowed / trade_expert`，任何一项为否都会在进度里标黄并说明原因（终端按钮没开 / 券商或投资者密码禁止交易 / 账户禁止 EA 交易）。

已在列表里的账号（账号 + 服务器相同）再次「添加并登录」只会更新密码、分组、名称，不会重复添加。「仅添加」只保存账户不登录；原来的「导入 CSV」仍可用。

## 六、服务器列表导入（只读）

设置 → **服务器列表 → 从已有 MT5 导入服务器列表**：
- 程序列出 `D:\15`、各磁盘常见位置里找到的 MT5，以及（只有你打开这个窗口时）`%APPDATA%\MetaQuotes\Terminal\*\origin.txt` 对应的数据目录；也可以手动填文件夹（如 `D:\1`、`D:\MT5\IC Markets`、`D:\P40`，或 MT5 里「文件 → 打开数据文件夹」打开的那个目录）。
- 只**读取**那份 MT5 的 `Config\servers.dat`，复制到 `data\servers\servers.dat`（上一份保留为 `.prev`）；**从不往那些文件夹写任何东西**，也不会关闭、改动正在运行的 MT5。程序自己的 `terminals\` 里的副本不能当来源。
- 导入后，每个**没在运行**的副本在下次启动时用上新列表；正在运行的副本要先断开（或重启）才会生效。
- 限制：`servers.dat` 是 MT5 的内部文件，格式可能随版本变化；最稳妥的来源是**已经登录过同一券商**的 MT5。实在找不到服务器时，可以用 `创建终端副本.bat --open <账号>` 打开该副本，在「文件 → 登录交易账户 / 开新账户」里搜索券商名称，登录一次后关闭。

## 七、使用

**账号页**：「添加并登录」（见上）；「仅添加」手动填写完整信息（备注、账号、交易密码、服务器、分组 主仓/跟单/测试、手数倍数、品种后缀/映射；终端路径留空 = `terminals\<账号>\terminal64.exe`），或导入 CSV。勾选后：
- **批量登录**：每个账户启动一个独立的工作进程（MetaTrader5 包一个进程只能连一个终端），终端没运行就由程序以 `/portable` 启动它，然后登录，之后每 1.5 秒刷新余额/净值/浮盈/持仓/挂单。
- **断开**：断开 Python 连接（默认不关闭终端；可在设置里改为同时关闭本程序启动的终端）。
- 编辑 / 停用 / 删除；状态列鼠标悬停可看失败原因；终端列显示"算法交易 开/关"。

**交易页 · 快捷交易面板**（最上面）：见「〇、本次更新」。接口：`GET /api/quick/summary?symbol=&accounts=`（只读汇总）、`POST /api/quick/action`（buy / sell / pair / close_long / close_short / close_profit / close_loss / nuke）、`POST /api/quick/auto`（自动全平，金额 0 = 取消；状态保存在 `data\quick_auto.json`）。

**交易页 · 高级批量操作**（面板下面，点开；对账号页已勾选、已在线的账户）：
- **批量下单**：市价买/卖，或买入/卖出限价、止损挂单；止损止盈可按"价格"或"点数（离开仓价）"填写；魔术号、注释。
- **手数模式**：固定手数 / 按账户倍数（账户里设置的倍数）/ 按净值比例（`手数 × 账户净值 ÷ 基准净值`）；缩放可以只对某些分组生效（默认「跟单」）。手数会按每个品种的步长向下取整，低于最小手数的账户会报错而不是偷偷放大。
- 下单前弹出**逐账户手数预览**，确认后才执行。
- **批量平仓**：全平、平多、平空、平盈利单、平亏损单、按品种平、按魔术号平、单笔平仓；撤销全部挂单。
- **批量改止损/止盈**：留空不改、填 0 清除，可按品种过滤。
- 已选在线敞口（按品种汇总净手数）、持仓表、挂单表。

**策略页**：
- **1 上传 EA 到 EA 库**：选择 `.ex5` 和可选的 `.set`，存到 `data\ea_library\`，只需上传一次。
- **2 一键分发到账户**：点「分发…」，选择：EA、参数文件、品种（券商实际名称，默认 USDJPYc；各账户设置的后缀/映射会自动套用，账户里没有这个品种时会自动改成唯一的相近品种或给出可选列表）、周期（默认 M15）、起始魔术号；
  - **每个账户魔术号自动 +1**（第 1 个账户 880000，第 2 个 880001 …，方便区分和“按魔术号平仓”）；
  - **魔术号参数名**（可选，例如 `MagicNumber`）：填了才会为每个账户生成自己的参数文件 `MQL5\Presets\fleet_<EA>_<账号>.set`，把这个参数改成该账户的魔术号；不填则 EA 用参数文件/默认值里的魔术号；
  - **按分组使用不同参数文件**（选了多个分组时出现，例如主仓和跟单用不同手数）；
  - **替换已有的同名 EA**（默认开）：重启前从该终端的图表文件里去掉同名 EA，避免同一 EA 重复挂载；
  - **同时处理**几个账户（1~4，默认 2）。
  点「分发」后每个账户依次：没登录的先自动登录 → 复制 EA 文件 → 重启终端 → 挂载 EA → 校验（读取该终端本次启动后的日志，找到“EA 加载成功”记为成功；20 秒内没找到相关日志记为“请到终端确认”的提醒，不算失败）。
- **一键停止 / 一键移除（已勾选账户）**：对勾选的账户停止 EA（从图表去掉并重启终端）或连同文件一起移除，同样显示每个账户的进度。
- 原理：先检查品种 → 把文件复制到该终端的 `MQL5\Experts\Fleet\`（`.set` 到 `MQL5\Presets\`）→ 正常关闭这个（本程序启动的）终端 → 在它自己的图表配置 `MQL5\Profiles\Charts\Default\` 里写一个挂着该 EA 的图表文件（品种、周期、EA 参数取自参数文件/账户魔术号；旧的同名 EA 图表和普通图表移到 `fleet_backup\`）→ 重新启动终端，终端自己加载这个图表和 EA → 读终端日志确认 EA 已加载。因为 EA 写在图表配置里，终端以后自动升级、重启、关了再开，EA 都会自动恢复。（日志里找不到加载记录时会退回用 MT5 启动配置 `[StartUp]` 再挂一次，并提醒。）**停止**：正常关闭该终端，从图表配置里删掉对应 EA 段落（原文件备份为 `.chr.fleetbak`），恢复一个默认品种的普通图表，再重新启动。每次部署/停止，该账户会离线约 10~30 秒。EA 的实际魔术号以 EA 参数/.set 为准，这里填写的魔术号用于记录和"按魔术号平仓"。

**收益页（首页，打开程序第一个看到的页面）**：浅色实时“收益台”，布局和动效参照参考视频，全部是本机 canvas 动画，不联网也能用，切到别的页面或最小化浏览器时自动暂停。数据全部来自真实终端：
- **顶部**：在线终端数、“实时”状态灯、当前时间。
- **指标条**：净值 = 范围内在线账户的净值合计（起点 = 今天第一次采样的净值）；总盈亏 = 持仓浮盈 + 今日已平仓盈亏；运行时长 = 程序运行时长；交易状态 = 实盘 · 已连接/未连接，每个小方块代表一个账户（绿/红 = 在线，橙 = 出错，灰 = 离线）。
- **// 净值曲线**：程序每 5 秒记录一次在线账户的净值合计（保留 13 小时，存在 `data\logs\equity-YYYYMMDD.jsonl`，重启后接着画），曲线会延伸、自动缩放；切到“已平仓”看近 30 天的平仓累计曲线。
- **// 活动日志**：操作日志 + 自动识别到的开仓 / 平仓 / 部分平仓（包括 EA 自己下的单），颜色对应账户。
- **盈亏分布山脊图**：每笔平仓盈亏的分布（按 σ 标准化），每一条山脊是一个滚动窗口；粉色区域是 +1.5σ 以外的大赢单尾部；左侧是笔数、尾部占比、平均赢/平均亏、单笔均值、最大单笔。
- **账户品种和弦图**：账户 → 品种的持仓手数流向（没有持仓时用最近 7 天的成交）；持仓笔数、失败操作数。
- **策略立方体**：旋转的五维超立方体（纯装饰，有新成交时会转得更快），旁边是账户 / 持仓 / 品种 / 策略数量。
- **跟单关系图**：按分组画出 主仓 → 跟单 → 其他 的关系，小点是各账户的持仓（蓝 = 盈利，粉 = 亏损），粒子沿虚线流动，有新成交时会成批流过；右侧是今日盈亏、最大回撤、盈利因子、胜率和近 60 天每日盈亏分布。
- **头像行**：每个账户一张卡片（像素头像按账号自动生成，名字 = 备注，角色 = 分组），有成交或浮盈明显变化时卡片会亮起（绿 = 盈利，粉 = 亏损，蓝 = 开仓）。
- **// 经典统计**（页面底部，点开）：原来的今日/近 7 日/本月/今年已实现盈亏、累计曲线、1–12 月柱状图、胜率、盈亏比、最好/最差日、账户贡献、实时浮动；「全部账户 / 只看已选」也会同时作用于上面的收益台。
- 平仓记录（`history_deals_get`，含手续费、隔夜利息）由后台每 60 秒自动读取一次，有新平仓时 2 秒内刷新；这些都只是读取，不会对终端做任何修改。

**日志页**：每个账户每一步的成功/失败（含 MT5 返回码的中文说明），可只看失败、导出 CSV；同时按天保存在 `data\logs\fleet-YYYYMMDD.jsonl`。

**设置页**：默认品种与周期（USDJPYc / M15）、启动终端时只保留一个图表、重新打开程序时自动接管仍在运行的终端、模板 MT5（检测）、服务器列表导入、单笔最大手数、单次批量合计最大手数、滑点、刷新间隔、默认缩放分组、断开/退出时是否关闭本程序启动的终端、启动时自动打开「算法交易」、允许 EA 调用 DLL、一键登录/分发同时处理的账户数、交易页快捷面板免确认、启动配置文件编码；批量创建终端副本；关闭本程序启动的全部终端；退出程序。

## 八、安全机制

- **只有实盘模式**：每个批量操作（下单、平仓、改单、撤单、部署/停止策略）都会先弹出确认框，列出将影响的账户和内容，并有红色“实盘”提示；点确认后才会真实发送。
- **手数保护**：单笔超过上限的账户会被拦截；整批合计超过上限整批拦截（服务端强制，不依赖网页）。
- 同一时间只执行一个批量操作，避免重复点击。
- 密码用 **Windows DPAPI** 加密保存在 `data\accounts.json`（只有当前 Windows 用户能解开），不发往任何地方；网页接口不会返回密码。唯一的例外：启动终端时写入该副本目录的一次性 `fleet_xxxx.ini` 里有明文密码，登录完成后立刻零覆盖并删除（通常只存在几秒到几十秒）；之后由终端自己按 `KeepPrivate=1` 加密保存在副本的 `Config` 里。非 Windows 环境会退回 base64 混淆并在界面警告。
- 网页服务只监听 `127.0.0.1`，接口需要页面内的随机令牌并校验 Host，其它网站无法跨站调用。
- 登录失败（如密码错误）不会自动反复重试，避免账户被锁；只有"登录成功后掉线"才会每 15 秒自动重连。

## 九、退出与终端关闭规则

- 退出方式：网页 **设置 → 退出程序**，或在黑色窗口按 **Ctrl+C**（直接点窗口右上角 × 也会尝试正常退出，但 Windows 只给几秒，建议用前两种）。
- 设置「退出程序时关闭（本程序启动的）终端」默认 **是**：只关闭 `data\launched.json` 里登记的进程（先正常关闭让终端保存图表，30 秒无响应才结束**那一个 PID**）。改成"否"则终端和 EA 继续运行，下次启动程序仍能认出它们。
- 你自己打开的任何 MT5（包括桌面上那份）在任何情况下都不会被关闭。
- **隐藏模式**（`一键启动.vbs`）没有窗口：退出请用网页左下角「退出程序」或 `停止后台.bat`（先让程序正常退出，按上面的设置决定是否关闭终端；程序没有响应时才强制结束本程序自己的进程，终端不受影响）。关掉浏览器不会退出程序，再双击「一键启动」即可回到面板。
- **重新打开程序**（`调试启动（显示窗口）.bat`，或一键启动时发现运行的是旧版本/没有响应）：如果上一次的黑色窗口没关、或者程序卡住，新启动的程序会先结束旧的本程序进程（直接结束，不走正常退出，所以不会按上面的设置去关终端），提示“已清理上次未退出的后台”，然后自动重新接管还在运行的受管终端（不重启它们，EA 继续跑）。不想自动清理可加参数 `--no-cleanup`。
- **MT5 自动升级**：受管终端第一次连上券商后，MT5 可能会自动下载新版本并重启自己（日志里有 `LiveUpdate`）。程序会等它重启完（最多 120 秒），认出这是自己启动的终端后自动接管，期间账户显示“终端已重启，正在重新连接”。升级一次后同一个副本就不会再升级；新建的副本如果是从旧版本模板复制的，第一次登录时仍可能升级一次，属正常现象。

## 十、打包成 exe（可选）
双击 `build_exe.bat`，生成 `MT5Fleet.exe` 放在程序目录（与 `terminals`、`data` 同级）即可双击运行。

## 十一、常见问题

| 现象 | 处理 |
|---|---|
| `无法导入 MetaTrader5 包` | 用的不是 64 位 Python 3.10+，或没运行「安装依赖.bat」。界面仍能打开，但不能登录。 |
| `[-6] 授权失败` | 账号/交易密码/服务器名不对；或该副本不认识这个服务器 → 设置页「从已有 MT5 导入服务器列表」后再登录；还不行就用 `创建终端副本.bat --open <账号>` 手动登录一次。 |
| 进度里「算法交易已开启」是黄色 | 按提示处理：终端工具栏「算法交易」没开、用的是投资者（只读）密码、或券商禁止该账户 EA 交易。 |
| 分发后「校验」是黄色 | 20 秒内日志里没看到 EA 加载记录（例如终端界面语言不同、EA 加载较慢），请打开该终端看图表右上角 EA 是否在运行。 |
| 找不到模板 MT5 | 设置页「模板 MT5」填入有 `terminal64.exe` 的文件夹并点「检测」。 |
| `[10027] 客户端禁止自动交易` | 终端工具栏的「算法交易」按钮没开。设置里“自动打开算法交易”保持“是”，或手动打开后再试。 |
| `已经在运行，但不是本程序启动的` | 你手动打开了 `terminals\<账号>` 里的 MT5，关掉它再批量登录。（本程序启动后被 MT5 自动升级重启的终端会自动接管，不会再报这个。） |
| `品种 XXX 不存在` / `这个账户没有品种 XXX` | 券商品种带后缀（如 `USDJPYc`、`XAUUSD.m`）或名字不同（`GOLD`）→ 分发时直接填券商的实际品种名，或在账户里设置品种后缀/映射。注意：不同账户类型品种名可能不同（例如美分账户是 `USDJPYc`，标准账户可能是 `USDJPY`）。 |
| 挂 EA 后面板没数据 / 不能交易 | 新版已自动处理 MT5 升级重启。如果还出现：看日志页该账户最后几条；终端日志里有 `AutoTrading disabled by server` 说明券商在服务器端禁止了这个账户的自动交易，需要联系券商；`No money` 是保证金不够。 |
| 打开软件提示后台已经在运行 / 端口被占用 | 新版启动时会自动处理：程序正常运行就直接打开网页，没有响应就清理后重新启动。直接再双击 `一键启动.vbs` 即可。 |
| 双击一键启动没反应 | 等 5~10 秒（第一次启动较慢）；仍没有网页就看 `data\logs\app-日期.log`，或双击 `调试启动（显示窗口）.bat` 看报错。杀毒软件拦截 .vbs 时选择允许。 |
| `[10019] 资金不足` / `[10016] 无效止损` | 账户保证金不够 / 止损止盈离现价太近，调整后重试。 |
| 端口被占用 | 程序会自动换端口，看黑色窗口里显示的地址。 |

## 十二、限制说明

- 本程序在 Linux 上用测试用的假 MT5 和假终端进程做了完整测试（一键登录、配置文件写入与删除、服务器列表导入、分发到多个账户、下单、平仓、改单、撤单、PID 隔离、退出关闭），**尚未在真实的 Windows + MT5 + 券商环境下实测**。请先用**最小手数**逐项验证，再逐步加大。
- EA 部署写的是 MT5 图表配置文件（`.chr`）；这个格式不是 MetaQuotes 公开文档，已按 MT5 自己保存的文件格式生成，但**还没有在你的真实 MT5 上验证**。分发后请打开一个终端看图表右上角 EA 是否在运行；万一没加载，程序会自动退回启动配置方式挂 EA 并提醒。其余依赖 MT5 官方启动配置文件（`/config`）；不同 MT5 版本若有差异，可在设置里切换配置文件编码，或手动在终端里挂 EA（本程序的交易功能不受影响）。
- 每次分发/停止 EA 都要重启对应终端（离线约 10~30 秒），并会在新图表上挂 EA。
- 服务器查找依赖终端自己的搜索功能和导入的 `servers.dat`；新副本第一次连接一个陌生券商可能需要重试或导入服务器列表。
- 分发后的“校验”靠读取终端日志里的加载记录，日志措辞随 MT5 版本/语言可能不同；没找到时只提醒，不判失败。
- 每账户不同魔术号只有在填写了“魔术号参数名”时才会写进 EA 参数；否则 EA 用自己的魔术号。
- 只支持 Windows（MetaTrader5 Python 包只有 Windows 版）。

## 十三、开发者说明（普通用户不用看）

自动化测试使用内置的假 MT5，不连接任何券商：`python app.py --mock`（数据单独存在 `data_mock\`；加环境变量 `FLEET_MOCK_AUTOTRADE=0` 关闭随机成交），然后运行 `tests\test_mock_api.py`；终端隔离测试见 `tests\test_isolation.py`；真实代码路径（不用 `--mock`）的一键登录/分发测试：先 `cc -O2 -o /tmp/fake/terminal64.exe tests/fake_terminal.c` 编译假终端，再 `python tests/test_real_flow.py /tmp/fake/terminal64.exe`（使用 `tests/fake_mt5` 里的假 MetaTrader5 包和临时目录 `FLEET_TERMINALS_ROOT`）。一键启动/停止后台：`python tests/test_launch.py`。便携版打包脚本：`tools/build_portable.py`（只能在 Windows 上运行）。`--mock` 只用于测试，不要用于实际交易。

## 十四、便携版（复制到别的电脑一键使用）

- 生成：在 `D:\15` 双击 **`打包便携版.bat`**（需要联网下载 Python 嵌入版和依赖，约 2~5 分钟）。生成 `D:\15\新建文件夹\MT5批量终端\` 和 `D:\15\新建文件夹\MT5批量终端.zip`。不会动正在运行的程序、`data` 和 `terminals`。
- 内容：`python\`（官方 Python 3.13 64 位嵌入版 + fastapi / uvicorn / psutil / MetaTrader5 / numpy 等全部依赖）、`MT5模板\`（从 `D:\15\MT5模板` 复制，去掉了历史数据、日志、测试器缓存、MetaEditor 和卸载程序、保存的账户信息，保留服务器列表）、程序文件、`data\ea_library`（已上传的 EA）、`一键启动.vbs`、`停止后台.bat`、`调试启动（显示窗口）.bat`、`使用说明.txt`。
- 使用：整个文件夹（或 zip 解压后）放到任意位置（中文、空格路径都行），双击 `一键启动.vbs`。要求 Windows 10/11 64 位，不用安装 Python。
- 不带的东西：账户列表和密码（`accounts.json` 里的密码用 Windows DPAPI 按“这台电脑 + 这个用户”加密，换电脑无法解密）、`terminals\<账号>` 里的终端副本。新电脑上在面板「添加并登录」即可，副本会从 `MT5模板` 自动生成。
- MT5模板 是 build 6246（2026-10-08 用官方安装程序安装到单独文件夹后复制，服务器列表换成这台电脑上最全的一份，191 个服务器）。以后 MT5 出新版本时，第一次登录后可能自动升级一次，程序会自动等待并接管。
